# 작은 배낭 상점

작은 진열대(6×5)에 상품을 채우고, 맞닿은 상품끼리의 조합으로 8일 동안 매출을 올리는 배치 전략 웹게임. 서버 없이 정적 파일만으로 돈다.

게임 주소: https://webgame-kr.github.io/shop/ (GitHub Pages, `main` 브랜치 최상위)

## 실행

ES 모듈을 쓰므로 `file://`이 아니라 아무 정적 서버로 연다.

```bash
python -m http.server 3600
```

저장소 폴더에서 실행하고 `http://localhost:3600`으로 연다.

## 구조

| 파일 | 내용 |
|---|---|
| `js/rules.js` | 상품 12종, 모양 회전, 겹침 판정, 하루 수익 계산, 등급. DOM 없음 |
| `js/game.js` | 한 판의 상태(JSON 하나): 후보 제시(시드 고정), 선택·배치·이동·폐기·넘기기, 되돌리기, 영업 정산 |
| `js/ui.js` | 시작·플레이·정산·결과 화면, 선택 후 위치 누르기(끌기는 보조), 첫 플레이 안내, 자동 저장 |
| `js/card.js` | 인스타 결과 카드 1080×1920 이미지 |
| `img/` | 상품 일러스트 12종(디자인 시안 10_Icons에서 잘라낸 투명 PNG) |
| `js/sound.js`, `sound/` | 효과음 21개와 배경음악 루프(WAV). 처음엔 꺼져 있고, 켤 때 처음 받아 Web Audio로 재생 |
| `scripts/simulate.js` | 봇으로 여러 판을 돌려 매출 분포와 등급 비율을 본다 |

## 테스트와 수치 검증

```bash
node --test test/
node scripts/simulate.js 300
```

등급 기준은 기획서 시험값(260/340/420)에서 320/420/520으로 올렸다. 시뮬레이션에서 아무 후보나 골라 처음 빈칸에 놓는 봇이 중앙값 323, 당장 수익만 보는 봇이 중앙값 492였기 때문이다. 실제 플레이 후 `js/rules.js`의 `GRADES`를 다시 조정한다.

## 디자인

2026.11.02 디자인 시안을 따른다. 배경 `#F3EADB`, 글자 `#2A2118`, 주 색(차양 초록) `#2F6B4F`, 강조 `#E07B39`, 진열대 나무 `#B9814C`, 빈 칸 `#EED9B6`. 제목·숫자·큰 버튼은 Jua, 본문은 Noto Sans KR(Google Fonts). 시안에 따라 티셔츠는 장화로 바뀌었고, 예전 저장 데이터의 `tshirt`는 불러올 때 `boots`로 바꾼다.

시안의 결과 화면은 등급 구간을 260/340/420으로 그렸지만, 게임은 위의 이유로 320/420/520을 쓴다.

## 소리

기획서대로 처음엔 꺼져 있다. 시작 화면 왼쪽 아래 버튼은 효과음과 배경음악을 함께 켜고 끄고, 메뉴(도움말)에서는 따로 켤 수 있다. 설정은 `small-shop:sound`에 저장한다. 다른 탭으로 가면 소리를 멈춘다.

| 소리 | 언제 |
|---|---|
| `ui_tap_1~3` | 일반 버튼 |
| `item_pick` | 후보 고르기 |
| `item_place_1~3`, `combo_spark` | 상품 놓기, 새 보너스가 생겼을 때 |
| `item_rotate`, `place_invalid`, `undo`, `discard` | 회전, 놓을 수 없는 자리, 되돌리기, 버리기 |
| `open_shop`, `coin_tick_1~5`, `day_total` | 영업 시작, 정산 화면의 상품별 수익, 합계 |
| `grade_reveal`, `new_record` | 결과 등급, 최고 기록 갱신 |
| `bgm_loop` | 배경음악(21초 반복) |

## 저장

`localStorage`에 `small-shop:run`(진행 중인 판, 되돌리기 기록 포함), `small-shop:best`(개인 최고), `small-shop:tutorial-done`을 둔다. 후보는 시드와 난수 상태가 함께 저장되므로 새로고침해도 바뀌지 않는다.
