# 마왕님, 내일 갚겠습니다

마왕에게 상점을 빌린 상인이 되어, 상품을 합성하고 수상한 계약을 맺으며 매일 오르는 납부액을 버티는 판타지 상점 생존 웹게임. 서버 없이 정적 파일만으로 돈다.

게임 주소: https://webgame-kr.github.io/shop/ (GitHub Pages, `main` 브랜치 최상위)

작은 배낭 상점의 틀(진열대 배치·회전·미리보기, 공유 카드, 사운드 구조)을 그대로 쓰고 규칙과 화면을 이 기획으로 바꿨다. 작은 배낭 상점은 이 저장소의 커밋 `333dda8`까지에 남아 있다.

## 실행

ES 모듈을 쓰므로 `file://`이 아니라 아무 정적 서버로 연다.

```bash
python -m http.server 3600
```

저장소 폴더에서 실행하고 `http://localhost:3600`으로 연다.

## 규칙 요약

- 영혼의 불꽃 3개로 시작. 오늘 매출이 납부액에 못 미치면 1개가 꺼지고(부족분이 커도 1개), 0개가 되면 압류.
- 새 판은 시작 분야(6개 중 하나)를 고르고 시작한다. 첫 주력 단골을 얻거나 10일 차가 끝날 때까지 입고 1번 자리가 그 분야에서 나오고, 그 분야 손님은 2일 차에 처음 온다(단골 전에는 방문 간격 상한 4일).
- 매일 후보 3개 중 1개를 고르는 입고를 2번. 자리마다 역할이 있다: 1번 주력 단골 분야(없으면 시작 분야) · 2번 보유 상품(합성 재료가 모자란 것 우선) · 3번 새 상품(최근 덜 나온 분야 우선, 독점 입고 계약이 이 자리를 쓴다). 전체 새로고침은 자리 역할을 유지하고, 무료 이용권(최대 2장)은 1번 자리만 다시 뽑는다. 진열대는 5×4에서 시작해 최대 7×6.
- 상품 42종: 연금술·모험 장비·마법 잡화 8종씩, 마계 식품·보물·귀금속·마수·알 6종씩. 효과 문구는 확장안 표와 신규 분야 기획서를 따른다. 지원 효과는 기본값과 등급만 보고 계산해 서로를 다시 키우지 않는다.
- 같은 상품·같은 등급 3개 → 한 등급 위 1개(약 2.4배). 놓지 않은 새 상품도 재료가 된다.
- 마수: 알로 들어와 기본 매출이 낮다. 알마다 성장 조건이 있고, 조건을 채운 채 영업이 끝나면 성장도 +1, 정령 둥지와 붙어 있으면 +1 더(중첩 없음). 2가 되면 성장 완료, 새 매출은 다음 영업부터. 알은 합성할 수 없고, 자라도 칸 모양은 그대로다.
- 변이: 한 상품 종류가 처음 Ⅱ등급이 되면 두 변이 중 하나를 고른다. 그 판 동안 그 종류의 Ⅱ등급 이상 전체에 적용. 48개 변이는 확장안 예시 12쌍을 그대로 쓰고, 나머지는 같은 원칙(자기 매출 집중 / 주변 지원 / 조건 달성 / 특정 손님 전문화)으로 채웠다.
- 단골: 분야형 손님 여섯 집단(마녀·모험가·마법학교·오우거 미식회·드워프 보석상·마수 사육사)만 단골이 된다. 고블린·귀족·떠돌이는 특별 손님으로만 온다. 손님이 온 날 호감 조건을 채운 채 영업하면 호감도 +1(방문당 최대 1). 친밀도 단계 1 관심 고객 · 2 단골(제안) · 4 친한 단골 · 6 VIP. 단골은 최대 두 집단, 자리가 차면 교체(떠난 집단의 호감은 0)하거나 거절한다.
- 주력 단골: 첫 단골이 주력이 되어 입고 1번 자리를 자기 분야로 채운다. 결산일에 성공하면 주력 보상 하나(무료 다시 뽑기 이용권 · 친한 단골이면 그 분야 Ⅰ등급 상품 선택 · VIP면 Ⅱ등급 상품 선택)를 받고, 그 뒤 주력을 바꿀 수 있다(다음 날부터 적용). 장부 계약은 주력 단골을 먼저 데려간다.
- 정상 납부 후 남은 매출은 잔금. 잔금으로 다시 뽑기·추가 입고·진열대 확장을 산다. 잔금으로 부족분을 메우지는 않는다.
- 계약 24종: 즉시 거래 8 · 기간형 8 · 조건형 8. 3·6·8·11·13·16…일에 유형별로 하나씩 제안되고, 하나에 서명하거나 모두 거절해야 그날 영업할 수 있다. 기간형·조건형은 합쳐서 두 개까지, 즉시 거래는 자리를 차지하지 않는다. 조건형은 계약금을 먼저 내고 실패하면 계약금만 잃는다. 빚의 유예는 상환일과 금액을 수락 전에 보여 주고, 상환 전에는 다시 제안되지 않는다.
- 5일마다 결산일: 납부액 ×1.35, 성공하면 성장 보상 3개 중 1개(우선 입고 지정, 분야 강화, 진열대 확장, 불꽃 회복 등). 우선 입고는 한 종류만, 매번 보장되지 않으며(한 칸에서 다른 후보 합의 1.5배까지), 다음 결산일에 바꿀 수 있다.
- 납부 실패 다음 날엔 마왕의 유예(후보 무료 다시 뽑기 1번).
- 기록은 생존 일수, 같으면 누적 매출.

## 텍스트 테스트 버전 (Claude가 플레이)

화면 없이 명령 한 줄씩 한 판을 진행한다. Claude 같은 에이전트가 직접 플레이하며 규칙·밸런스·버그를 확인하는 용도이고, 본 게임 저장(브라우저)과는 따로다. 상태는 `.play-state.json`(현재 폴더, `PLAY_STATE` 환경변수로 변경)에 남는다.

```bash
node scripts/play.js new 42 food     # 시드 42, 시작 분야 마계 식품
node scripts/play.js pick 1          # 입고 후보 1번
node scripts/play.js place 0 0       # (0,0)에 놓기, 회전은 세 번째 숫자
node scripts/play.js open            # 영업하고 납부 판정
node scripts/play.js help            # 전체 명령
```

명령마다 진열대(상품 번호 격자), 상품별 예상 매출과 보너스, 알의 성장 예측, 손님 호감 조건 충족 여부, 그리고 지금 해야 하는 결정(입고 후보·계약·변이·결산 보상·주력 단골·단골 제안)과 쓸 수 있는 명령을 글로 보여 준다. 같은 시드면 같은 판이 나와 버그를 다시 만들 수 있다.

Claude에게 맡길 때는 이렇게 부탁하면 된다: "shop 폴더에서 `node scripts/play.js help`를 보고 한 판 플레이하면서 이상한 점을 찾아 줘."

## 저장

`localStorage`에 `demon-shop:run`(진행 중인 판, 되돌리기 기록 포함, 형식 버전 4), `demon-shop:best`(최고 기록), `demon-shop:tutorial-done`, `demon-shop:sound`(소리 설정)을 둔다. 무작위는 시드와 난수 상태를 함께 저장하고, 손님 순서는 시드에서 따로 뽑아 새로고침해도 후보·손님·계약이 바뀌지 않는다. 이전 형식(버전 3 이하)의 진행 중 판은 이어 할 수 없고 새로 시작한다.
