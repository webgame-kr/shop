# 마왕님, 내일 갚겠습니다

마왕에게 상점을 빌린 상인이 되어, 상품을 합성하고 수상한 계약을 맺으며 매일 오르는 납부액을 버티는 판타지 상점 생존 웹게임. 서버 없이 정적 파일만으로 돈다.

게임 주소: https://webgame-kr.github.io/shop/ (GitHub Pages, `main` 브랜치 최상위)

작은 배낭 상점의 틀(진열대 배치·회전·미리보기, 공유 카드, 사운드 구조)을 그대로 쓰고 규칙과 화면을 이 기획으로 바꿨다. 작은 배낭 상점은 이 저장소의 커밋 `333dda8`까지에 남아 있다.

## 디자인

2026.11.02 디자인 시안과 확장판 시안(10~16)을 따른다. 화면 흐름은 시작 → 영업 예고(아침) → 입고(후보 역할) → 상점 정리(합성 미리보기·변이·상품 상세) → 마왕의 계약(즉시·기간·조건) → 납부와 판정(영수증) → 결산 보상(우선 입고) → 단골 제안·교체 → … → 압류 통지서.

바탕 `#1D1524`, 카드 `#2A1F33`, 글자 `#F4E9D8`, 불꽃·주요 버튼 `#FF8A3D`, 잔금·등급 `#F2C46B`, 양피지 `#F1E4C8`, 봉인·압류 도장 `#9E2B25`, 분야 색 연금술 `#2F7558`·모험 장비 `#3F5F8C`·마법 잡화 `#7448A3`. 숫자·제목·버튼은 도현체, 계약서·마왕 대사·통지서는 고운바탕, 설명은 Noto Sans KR(Google Fonts).

`img/`의 상품 일러스트 24종, 손님 초상 6종, 마왕, 불꽃은 시안 PNG(07_Items, 16_ItemsPlus, 08_Guests, 01_Main)에서 잘라 배경을 투명하게 만든 것이다. 등급은 로마 숫자 태그(Ⅰ~)와 Ⅱ 금테, Ⅲ 보라 빛, Ⅳ 이상 주황 빛과 숫자 배지. 변이는 상품 오른쪽 위 육각형(금색 = A, 민트 = B, 변이 이름 첫 글자, Ⅰ등급에는 없음).

## 실행

ES 모듈을 쓰므로 `file://`이 아니라 아무 정적 서버로 연다.

```bash
python -m http.server 3600
```

저장소 폴더에서 실행하고 `http://localhost:3600`으로 연다.

## 규칙 요약

- 영혼의 불꽃 3개로 시작. 오늘 매출이 납부액에 못 미치면 1개가 꺼지고(부족분이 커도 1개), 0개가 되면 압류.
- 매일 후보 3개 중 1개를 고르는 입고를 2번. 후보는 역할로 나뉜다: 진열 중인 상품과 같은 종류 · 오늘/내일 손님·단골이 좋아하는 상품 · 새 선택. 진열대는 5×4에서 시작해 최대 7×6.
- 상품 24종(분야별 8종). 효과 문구는 확장안 표를 따른다. 지원 효과는 기본값과 등급만 보고 계산해 서로를 다시 키우지 않는다.
- 같은 상품·같은 등급 3개 → 한 등급 위 1개(약 2.4배). 놓지 않은 새 상품도 재료가 된다.
- 변이: 한 상품 종류가 처음 Ⅱ등급이 되면 두 변이 중 하나를 고른다. 그 판 동안 그 종류의 Ⅱ등급 이상 전체에 적용. 48개 변이는 확장안 예시 12쌍을 그대로 쓰고, 나머지는 같은 원칙(자기 매출 집중 / 주변 지원 / 조건 달성 / 특정 손님 전문화)으로 채웠다.
- 단골: 특별 손님이 오는 날 그 손님의 선호 조건을 채운 채 영업하면 호감도 +1(방문당 최대 1). 2가 되면 단골 제안, 최대 두 집단. 자리가 차면 교체하거나 거절(거절하면 호감도 초기화). 불꽃을 잃어도 떠나지 않고, 계약이나 직접 교체로만 끝난다. 단골 효과는 매출 숫자가 아니라 방문 보장·입고 비중·방문 보너스·새로고침 할인·중급 구매 기회·추가 입고 할인에 작용한다.
- 정상 납부 후 남은 매출은 잔금. 잔금으로 다시 뽑기·추가 입고·진열대 확장을 산다. 잔금으로 부족분을 메우지는 않는다.
- 계약 24종: 즉시 거래 8 · 기간형 8 · 조건형 8. 3·6·8·11·13·16…일에 유형별로 하나씩 제안되고, 하나에 서명하거나 모두 거절해야 그날 영업할 수 있다. 기간형·조건형은 합쳐서 두 개까지, 즉시 거래는 자리를 차지하지 않는다. 조건형은 계약금을 먼저 내고 실패하면 계약금만 잃는다. 빚의 유예는 상환일과 금액을 수락 전에 보여 주고, 상환 전에는 다시 제안되지 않는다.
- 5일마다 결산일: 납부액 ×1.35, 성공하면 성장 보상 3개 중 1개(우선 입고 지정, 분야 강화, 진열대 확장, 불꽃 회복 등). 우선 입고는 한 종류만, 매번 보장되지 않으며(한 칸에서 다른 후보 합의 1.5배까지), 다음 결산일에 바꿀 수 있다.
- 납부 실패 다음 날엔 마왕의 유예(후보 무료 다시 뽑기 1번).
- 기록은 생존 일수, 같으면 누적 매출.

## 구조

| 파일 | 내용 |
|---|---|
| `js/rules.js` | 상품 24종과 변이 48개, 등급, 모양 회전, 배치 판정, 하루 매출(기본 → 배치 → 변이 → 손님 → 계약 구분), 합성 재료 고르기. DOM 없음 |
| `js/game.js` | 한 판의 상태(JSON 하나): 납부액 곡선, 손님 순서와 단골 방문 보장, 역할별 입고 후보와 우선 입고, 합성·변이, 잔금 사용, 계약 24종, 조건형 판정, 호감도·단골, 영업 판정, 결산 보상, 되돌리기 |
| `js/ui.js` | 시작·아침·입고·정리·계약·판정·변이·단골·결산·압류 통지서 화면, 선택 후 위치 누르기(끌기는 보조), 첫 플레이 안내, 자동 저장 |
| `js/card.js` | 공유용 압류 통지서 이미지 1080×1920 |
| `js/sound.js`, `sound/` | 마왕님 사운드 키트(확장판): 효과음 49개와 배경음악. 처음엔 꺼져 있다 |
| `img/` | 상품 일러스트 24종, 손님 초상 6종, 마왕, 불꽃 |
| `scripts/simulate.js` | 봇으로 여러 판을 돌려 생존 일수 분포를 본다 |

## 테스트와 수치 검증

```bash
node --test test/
node scripts/simulate.js 30
```

현재 납부액 곡선(`basePay`): 1일 6 · 5일 41(결산) · 10일 101 · 20일 292 · 30일 574. 확장 규칙 기준 30판에서 아무 후보나 골라 처음 빈칸에 놓는 봇은 중앙값 13일, 당장 매출이 가장 오르는 수를 두고 자리가 모자라면 합성하는 봇은 중앙값 40일(최소 32, 최대 62)을 버틴다. 두 봇 모두 계약은 쓰지 않고, 변이는 항상 A를 고른다. 실제 플레이 후 `js/game.js`의 `basePay`, 상품 기본값, 계약 금액을 조정한다.

## 저장

`localStorage`에 `demon-shop:run`(진행 중인 판, 되돌리기 기록 포함, 형식 버전 3), `demon-shop:best`(최고 기록), `demon-shop:tutorial-done`, `demon-shop:sound`(소리 설정)을 둔다. 무작위는 시드와 난수 상태를 함께 저장하고, 손님 순서는 시드에서 따로 뽑아 새로고침해도 후보·손님·계약이 바뀌지 않는다. 확장 전(버전 2) 진행 중 판은 이어 할 수 없고 새로 시작한다.
