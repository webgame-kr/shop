# 마왕님, 내일 갚겠습니다

마왕에게 상점을 빌린 상인이 되어, 상품을 합성하고 수상한 계약을 맺으며 매일 오르는 납부액을 버티는 판타지 상점 생존 웹게임. 서버 없이 정적 파일만으로 돈다.

게임 주소: https://webgame-kr.github.io/shop/ (GitHub Pages, `main` 브랜치 최상위)

작은 배낭 상점의 틀(진열대 배치·회전·미리보기, 공유 카드, 사운드 구조)을 그대로 쓰고 규칙과 화면을 이 기획으로 바꿨다. 작은 배낭 상점은 이 저장소의 커밋 `333dda8`까지에 남아 있다.

## 디자인

2026.11.02 디자인 시안을 따른다. 화면 흐름은 시작 → 영업 예고(아침) → 입고·상점 정리(합성 미리보기) → 마왕의 계약 → 납부와 판정(영수증) → 압류 통지서. 바탕 `#1D1524`, 카드 `#2A1F33`, 글자 `#F4E9D8`, 불꽃·주요 버튼 `#FF8A3D`, 잔금·등급 `#F2C46B`, 양피지 `#F1E4C8`, 봉인·압류 도장 `#9E2B25`, 분야 색 연금술 `#2F7558`·모험 장비 `#3F5F8C`·마법 잡화 `#7448A3`. 숫자·제목·버튼은 도현체, 계약서·마왕 대사·통지서는 고운바탕, 설명은 Noto Sans KR(Google Fonts).

`img/`의 상품 일러스트 15종, 손님 초상 6종, 마왕, 불꽃은 시안 PNG(07_Items, 08_Guests, 01_Main)에서 잘라 배경을 투명하게 만든 것이다. 등급은 로마 숫자 태그(Ⅰ~)와 Ⅱ 금테, Ⅲ 보라 빛, Ⅳ 이상 주황 빛과 숫자 배지로 구분한다. 시안의 상품 효과 문구는 "밸런스 전 초안"이라 효과는 시뮬레이션으로 맞춘 기존 값을 쓰고, 칸 모양만 그림에 맞췄다(독병 1칸, 마도서·활은 세로가 기본).

## 실행

ES 모듈을 쓰므로 `file://`이 아니라 아무 정적 서버로 연다.

```bash
python -m http.server 3600
```

저장소 폴더에서 실행하고 `http://localhost:3600`으로 연다.

## 규칙 요약

- 영혼의 불꽃 3개로 시작. 오늘 매출이 납부액에 못 미치면 1개가 꺼지고(부족분이 커도 1개), 0개가 되면 압류.
- 매일 후보 3개 중 1개를 고르는 입고를 2번. 진열대는 5×4에서 시작해 최대 7×6.
- 같은 상품·같은 등급 3개 → 한 등급 위 1개. 등급당 기본 매출 약 2.4배라 셋을 따로 둔 것보다 매출은 적지만 칸이 빈다. 놓지 않은 새 상품도 재료가 된다.
- 정상 납부 후 남은 매출은 잔금. 잔금으로 다시 뽑기·추가 입고·진열대 확장을 산다. 잔금으로 부족분을 메우지는 않는다.
- 매일 특별 손님 1종(6종), 오늘과 내일 손님을 미리 보여 준다. 같은 손님은 사흘 안에 두 번 오지 않는다.
- 3·8·13…일에 마왕의 계약 3건 제안(10종, 기간형·횟수형만). 동시에 두 개까지.
- 5일마다 결산일: 납부액 ×1.35, 성공하면 성장 보상 3개 중 1개.
- 납부 실패 다음 날엔 마왕의 유예(후보 무료 다시 뽑기 1번).
- 기록은 생존 일수, 같으면 누적 매출.

## 구조

| 파일 | 내용 |
|---|---|
| `js/rules.js` | 상품 15종(연금술·모험 장비·마법 잡화)과 등급, 모양 회전, 배치 판정, 하루 매출(기본·배치·손님·계약·성장 구분), 합성 재료 고르기. DOM 없음 |
| `js/game.js` | 한 판의 상태(JSON 하나): 납부액 곡선, 손님 순서, 입고 후보, 합성, 잔금 사용, 계약, 영업 판정, 결산 보상, 되돌리기 |
| `js/ui.js` | 시작·플레이·정산·압류 통지서 화면, 선택 후 위치 누르기(끌기는 보조), 첫 플레이 안내, 자동 저장 |
| `js/card.js` | 공유용 압류 통지서 이미지 1080×1920 |
| `js/sound.js`, `sound/` | 마왕님 사운드 키트: 효과음 31개(계약 열기·서명·거절, 합성 준비·완성, 납부 성공·실패, 불꽃 꺼짐, 결산 종, 압류, 마왕 목소리 등)와 배경음악. 처음엔 꺼져 있다 |
| `img/` | 상품 일러스트 15종, 손님 초상 6종, 마왕, 불꽃 |
| `scripts/simulate.js` | 봇으로 여러 판을 돌려 생존 일수 분포를 본다 |

## 테스트와 수치 검증

```bash
node --test test/
node scripts/simulate.js 100
```

현재 납부액 곡선(`basePay`): 1일 6 · 5일 41(결산) · 10일 101 · 20일 292 · 30일 574. 40판 기준으로 아무 후보나 골라 처음 빈칸에 놓는 봇은 중앙값 12일, 당장 매출이 가장 오르는 수를 두고 자리가 모자라면 합성하는 봇은 중앙값 40일(최소 32, 최대 50)을 버틴다. 두 봇 모두 계약은 쓰지 않는다. 실제 플레이 후 `js/game.js`의 `basePay`와 결산 배수를 조정한다.

## 저장

`localStorage`에 `demon-shop:run`(진행 중인 판, 되돌리기 기록 포함), `demon-shop:best`(최고 기록), `demon-shop:tutorial-done`, `demon-shop:sound`(소리 설정)을 둔다. 무작위는 시드와 난수 상태를 함께 저장하고, 손님 순서는 시드에서 따로 뽑아 새로고침해도 후보·손님·계약이 바뀌지 않는다.
