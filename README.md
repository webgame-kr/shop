# 마왕님, 내일 갚겠습니다

마왕에게 상점을 빌린 상인이 되어, 상품을 합성하고 수상한 계약을 맺으며 매일 오르는 납부액을 버티는 판타지 상점 생존 웹게임. 서버 없이 정적 파일만으로 돈다.

게임 주소: https://webgame-kr.github.io/shop/ (GitHub Pages, `main` 브랜치 최상위)

작은 배낭 상점의 틀(진열대 배치·회전·미리보기, 정산 화면, 공유 카드, 사운드)을 그대로 쓰고 규칙과 화면을 이 기획으로 바꿨다. 작은 배낭 상점은 이 저장소의 커밋 `333dda8`까지에 남아 있다.

## 실행

ES 모듈을 쓰므로 `file://`이 아니라 아무 정적 서버로 연다.

```bash
python -m http.server 3600
```

저장소 폴더에서 실행하고 `http://localhost:3600`으로 연다.

## 규칙 요약

- 영혼의 불꽃 3개로 시작. 오늘 매출이 납부액에 못 미치면 1개가 꺼지고(부족분이 커도 1개), 0개가 되면 압류.
- 매일 후보 3개 중 1개를 고르는 입고를 2번. 진열대는 5×4에서 시작해 최대 7×6.
- 같은 상품·같은 등급 3개 → 한 등급 위 1개. 등급당 기본 매출 약 2.4배라 셋을 따로 둔 것보다 매출은 적지만 칸이 빈다. 놓지 않은 새 상품도 재료가 된다.
- 정상 납부 후 남은 매출은 잔금. 잔금으로 다시 뽑기·추가 입고·진열대 확장을 산다. 잔금으로 부족분을 메우지는 않는다.
- 매일 특별 손님 1종(6종), 오늘과 내일 손님을 미리 보여 준다. 같은 손님은 사흘 안에 두 번 오지 않는다.
- 3·8·13…일에 마왕의 계약 3건 제안(10종, 기간형·횟수형만). 동시에 두 개까지.
- 5일마다 결산일: 납부액 ×1.35, 성공하면 성장 보상 3개 중 1개.
- 납부 실패 다음 날엔 마왕의 유예(후보 무료 다시 뽑기 1번).
- 기록은 생존 일수, 같으면 누적 매출.

## 구조

| 파일 | 내용 |
|---|---|
| `js/rules.js` | 상품 15종(연금술·모험 장비·마법 잡화)과 등급, 모양 회전, 배치 판정, 하루 매출(기본·배치·손님·계약·성장 구분), 합성 재료 고르기. DOM 없음 |
| `js/game.js` | 한 판의 상태(JSON 하나): 납부액 곡선, 손님 순서, 입고 후보, 합성, 잔금 사용, 계약, 영업 판정, 결산 보상, 되돌리기 |
| `js/ui.js` | 시작·플레이·정산·압류 통지서 화면, 선택 후 위치 누르기(끌기는 보조), 첫 플레이 안내, 자동 저장 |
| `js/card.js` | 공유용 압류 통지서 이미지 1080×1920 |
| `js/sound.js`, `sound/` | 효과음 21개와 배경음악(작은 배낭 상점 사운드 키트). 처음엔 꺼져 있다 |
| `scripts/simulate.js` | 봇으로 여러 판을 돌려 생존 일수 분포를 본다 |

## 테스트와 수치 검증

```bash
node --test test/
node scripts/simulate.js 100
```

현재 납부액 곡선(`basePay`): 1일 6 · 5일 41(결산) · 10일 101 · 20일 292 · 30일 574. 100판 기준으로 아무 후보나 골라 처음 빈칸에 놓는 봇은 중앙값 12일, 당장 매출이 가장 오르는 수를 두고 자리가 모자라면 합성하는 봇은 중앙값 36일(최소 24, 최대 43)을 버틴다. 두 봇 모두 계약은 쓰지 않는다. 실제 플레이 후 `js/game.js`의 `basePay`와 결산 배수를 조정한다.

## 저장

`localStorage`에 `demon-shop:run`(진행 중인 판, 되돌리기 기록 포함), `demon-shop:best`(최고 기록), `demon-shop:tutorial-done`, `small-shop:sound`(소리 설정)을 둔다. 무작위는 시드와 난수 상태를 함께 저장하고, 손님 순서는 시드에서 따로 뽑아 새로고침해도 후보·손님·계약이 바뀌지 않는다.
